# Case study: Holzborste — same product, two executor modes

Two dogfood runs built the identical product (German one-pager for an artisanal
eco-toothbrush workshop: one-pager → contact form → OpenFreeMap dealer map →
fourth feature) on the same lean-verified schema, drift guard, hooks, and test
harness — with deliberately different executors:

- **Run 2 (`holzborste`, private)** — the schema's author driving the OpenSpec
  CLI directly in one session. No skill workflow used (that was the gap: the run
  tested the schema, not the skills). Expert context, zero cold-start cost.
- **Run 3 (`holzborste-v2`, private)** — 4 fresh, cold-start agents
  (zai/glm-5.3, thinking high), one per change, mandated to follow the
  `openspec init --agent pi` skill workflow (explore → propose → apply →
  archive) strictly. Supervisor (this repo's author) only verified, answered
  questions, resumed stalled sessions, and pushed. Never implemented.

## Headline numbers

| | Run 2 (author, no skills) | Run 3 (4 cold agents, skills) |
|---|---|---|
| Changes archived | 6 (incl. 2 emergent) | 4 |
| Wall time (git first→last) | **25 min** | ~97 min (+stalls/resumes) |
| `validate --strict` first-try | not always (author iterated) | **4/4 first-try** |
| Guard-blocked commits | 0 | **0** |
| `--no-verify` bypasses | 0 | 0 |
| Living spec | 17 reqs / 230 LOC | **17 reqs / 232 LOC** |
| Acceptance tests | 5 files / 23 pass | 10 files / 25 pass |
| Site code | 389 LOC (modular assets/) | 817 LOC (3 monolithic files) |
| MODIFIED-requirements discipline | held (by design) | held **twice unprompted** (contact form, dealer map) |
| Design gate | triaged by author | 1 real design.md (map vendoring) + 3 recorded skips |
| Spec markers in code | 0 | 0 |

The near-identical contract shape (17/17 requirements, 230 vs 232 spec LOC) from
four agents that never saw each other's sessions is the strongest signal: **the
schema + skills make the workflow agent-portable.** Cold agents hit 100%
first-try validation and zero guard blocks; every existing-test modification
was correctly routed through MODIFIED spec requirements; nobody touched the
living spec by hand, bypassed a hook, or left spec markers in code.

## What each mode is for

- **Run 2 speed (25 min, 6 changes)** comes from expert context and the
  author's freedom to spin *emergent* changes (nav-scroll-offset,
  konfigurator-hook) from friction it noticed. Cold agents did exactly what
  was asked — no more. If you want emergent hygiene changes from agents, ask
  for them explicitly (a standing "propose one improvement" task).
- **Run 3 correctness** came from the gates, not from talent: each agent was
  disposable, replaceable, and still landed the same contract. Onboarding cost
  was ~0 (skills + AGENTS.md), vs run 2's irreducible author knowledge.

## Findings ledger (schema/skill improvements surfaced by cold agents)

1. **Unsatisfiable scenario authored in propose** (Agent 2): "section fully
   inside 720px viewport" was geometrically impossible (702.6px section +
   64px scroll-padding). Only the red acceptance test + a measurement probe
   caught it. → Design-gate triage should ask: *is every scenario physically
   satisfiable on the target viewport/environment?*
2. **Archive leaves living spec uncommitted** (Agents 2+3): between
   `openspec archive --yes` and the archive commit, the full-scan guard is
   red (L2: code "changed after" the rewritten spec). Transient and expected —
   but the archive skill should say so, or archive+commit should be one step.
3. **Skill/CLI version drift** (Agents 1+4): skills generated by CLI 1.14.3
   reference `openspec context`/`store` and an `archive` instructions artifact
3. **Stale global CLI silently shadows npx** (Agents 1+4): skills generated
   by CLI 1.14.3 reference `openspec context`/`store`/`instructions` that the
   agents' runtime CLI lacked. Root cause (initially misattributed to
   upstream): a stale global `@fission-ai/openspec@1.1.1` on the supervisor's
   machine — `npx` prefers an already-installed global over the registry.
   Fix: `npm i -g @fission-ai/openspec@latest` (upstream npm was current all
   along; `archive` data-loss seen in run 3 is also fixed in current
   releases). Playbook rule: after `openspec init`, assert
   `openspec --version` matches before starting work.
4. **No artifact slot for test-contract changes** (Agent 3): when a new
   section legitimately breaks existing acceptance tests, agents route it
   through a task + MODIFIED requirements — works, but the schema could name
   this "test-contract migration" pattern explicitly.

## Infrastructure notes (pi harness, not schema)

- zai/glm-5.3 sessions die when the model attempts mid-task context
  compression — mis-fires as `caller_ping`, session exits (5 occurrences).
  Supervisor resume recovers in ~1 min each; work state survived every time
  (committed or on disk). Budget for it when orchestrating long agent runs.
- Intercom `ask` round-trips cost 2–5 min per stop; instruct agents to batch
  questions and default to autonomous continuation (they mostly did).

## Reproduce

Both repos are private on GitHub (`holzborste`, `holzborste-v2`); the schema,
guard, hooks, and smoke suite live in this repo. To re-run: copy
`openspec/` + `.githooks/` + harness into a fresh repo, `openspec init --agent
pi`, then spawn per-change agents with the cold-start brief pattern used here
(explore → propose → apply → archive, self-report, never bypass hooks).
